A presheaf is a generalized object

  • November 13, 2026
  • Hsu Ching Chung

I think I know why people like presheaves a lot: we can think of a presheaf as a generalized object.

Fix a measure space (\Omega , \mathcal {B}, m). The article considers more general elements in the following order:

  1. a deterministic real number x \in \mathbb {R}; it's just a real number.
  2. a stochastic real number x : \Omega \to \mathbb {R} is a measurable function from \Omega to \mathbb {R}, also called a random variable. (note \mathbb {R} is equipped with the Borel sigma algebra and Lebesgue measure)
  3. a stochastic element of a measurable space (X, \mathcal {M}) is a measurable function x : \Omega \to X.
  4. a stochastic set is a presheaf on the category of measurable sets E \subset \Omega (with inclusion as a poset) satisfying some gluing condition and an axiom related to null sets.

When I read items 1 and 2, I feel it does quite match the language of generalized elements. The measurable function x : \Omega \to \mathbb {R} is a morphism into \mathbb {R} in the category of measure spaces. It interprets the context \Omega as "randomness". A deterministic real number x \in \mathbb {R} is a constant function \Omega \to \mathbb {R}, \omega \mapsto x, or a global element x : 1 \to \mathbb {R}, where 1 is the terminal object in measure space, the singleton measure space. (Although they aren't: a morphism in the category of measure spaces is not just a measurable function, and I'm not even sure there exists a terminal object in the category of measure spaces or not. Defining the category of measure spaces needs more work then defining the category of measurable spaces.)

But item 3 shocked me! Replacing the codomain \mathbb {R} with a general measurable space X seems to be a natural step toward general cases. But when I realized it allows the codomain X to not live in the same category as the domain \Omega : a measure space \Omega has the σ-algebra structure \mathcal {B} with a specified measure m, but a measurable space X only requires a σ-algebra structure \mathcal {M}. It goes beyond the framework of generalized elements: it consider a "morphism" between objects in different categories. However, the assignment \Omega \mapsto \{\text {measurable functions from } \Omega \text { to } X\} is still great enough to form a presheaf! Presheaves seem to be the correct generalization; indeed, item 4 defines stochastic sets as an abstract presheaf rather than measurable functions between some spaces.

So the evolutionary tree of “elements of A” for an object A in a category \mathcal {C} goes like this:

  • If A is a "set", it already has the notion of "an element of A".
  • If A is not a set, we can consider the generalized elements of A, that is, the morphisms into A, equivalently, the contravariant hom-functor \operatorname {Hom}_\mathcal {C}(-, A).
  • In the spirit of generalized elements, the "social identity" of A is fully described by the “memory” \operatorname {Hom}_\mathcal {C}(\Gamma , A) from other objects \Gamma . If we can implant an artificial memory in each object \Gamma , i.e., assign a set F(\Gamma ) to each object \Gamma (of course, satisfying some compatible condition), we can create a virtual object F.

It is what a presheaf is! We may call a presheaf F a generalized object, for F can only be understood from the point of view of other objects. A fun fact: Denote the Yoneda embedding by A \mapsto \text {よ} A := \operatorname {Hom}_\mathcal {C}(-, A). In the presheaf category, the set of generalized elements of a generalized object F with the context \text {よ} A is indeed the artificial memory F(A) on A; in other words, \operatorname {Hom}_{\operatorname {Psh}(\mathcal {C})}(\text {よ} A, F) \cong F(A), exactly the Yoneda Lemma!

When a presheaf is representable, there exists an object A such that F \cong \text {よ} A. The generalized object F can be realized through a real object A!

Some morphisms should have different types?

  • November 13, 2026
  • Hsu Ching Chung

It also solves the itch of untyped language. In the last post, we saw some equations of morphisms in the form: f x \sigma = u \varphi where all morphisms have different roles: x is a generalized element, post-composition by f acts like mapping between generalized elements, pre-composition by \sigma acts like context substitution or changing the state of a generalized element, and u is a monomorphism used to test whether a generalized element belongs to the subobject determined by u (the membership relation x \in u is defined as x factors through u, i.e., x = u \varphi for some \varphi ).

Think of the generalized elements of A as a presheaf F = \operatorname {Hom}_\mathcal {C}(-, A); it separates the role of f, x, \sigma nicely:

  • Given a context \Gamma , a generalized element with context \Gamma is an element x \in F(\Gamma ) of the presheaf F evaluated at \Gamma .
  • A morphism f : A \to B lifts to a natural transformation \eta : F \to G, where F = \operatorname {Hom}_\mathcal {C}(-, A), G = \operatorname {Hom}_\mathcal {C}(-, B), and for any context \Gamma , the component \eta _\Gamma : F(\Gamma ) \to G(\Gamma ), x \mapsto f x maps a generalized element by post-composition by f.
  • The functoriality of F = \operatorname {Hom}_\mathcal {C}(-, A) at \sigma : \Delta \to \Gamma is exactly the pre-composition by \sigma , F\sigma : F(\Gamma ) \to F(\Delta ), x \mapsto x \sigma .

(The correct type of u should be captured by how it factors other generalized elements, i.e., we should consider the set \{x \mid x \in u\}. Our story does not teach us how we should think of u, but I guess it is related to sieve?)

By the way, his blog has a clear storyline, notes some possible confusion about notation, and the motivation for the definitions. Nice to learn.

An intrinsic characterization of flat modules

  • November 13, 2026
  • Hsu Ching Chung

In our algebra class, the flat modules are defined using a categorical property: fix a ring A (follow the convention in Atiyah-Macdonald; all rings are commutative with unity 1), an A-module M is flat if the covariant functor defined by tensoring with M over A, (M \otimes _A -) : A\text {-Mod} \to A\text {-Mod}, N \mapsto M \otimes _A N is an exact functor. In general, I quite like definitions using categorical properties; they feel concise and mysterious, and when you unpack them, they often contain a lot of meaningful information. But in this case, it is too mysterious; I still don't know the intuition behind what a flat module is. Although classical logic is not the reason for this confusion, I am still curious how constructive mathematicians think about flat modules. I ended up finding the word "syzygy" in Chapter VIII, Flat module, of Commutative algebra: Constructive methods. Finite projective modules.

Definition Syzygy

  • November 13, 2026
  • Hsu Ching Chung

Given a ring A and an A-module M. A tuple (a_1, \dots , a_n, x_1, \dots , x_n), a_i \in A, x_i \in M, is called a syzygy if a_1 x_1 + \dots + a_n x_n = 0. In matrix form, a syzygy is a pair (L, X), where L \in A_{1 \times n} and X \in M_{n \times 1}, such that LX = 0.

Syzygy is an interesting name; according to the Cambridge Dictionary, a syzygy is an arrangement in which two or more planets, stars, etc. are in a straight line. It describes an image in a module: fix some elements x_1, \dots , x_n in M, like planets, and vary the coefficients a_1, \dots , a_n in A; we see a_1 x_1, \dots , a_n x_n moving around as planets move in a solar system. When the special timing arises, the sum of the moving planets, a_1 x_1 + \dots + a_n x_n, is zero; this is when a syzygy occurs. What a vivid name.

Figuring out why a syzygy occurred can provide insight into the elements of the underlying module. A finite set of elements x_1, \dots , x_n is linearly independent over A if, for any syzygy LX = 0 with X = [x_1, \dots , x_n], we have L = 0. It is the most "free" situation: there are no relations among x_1, \dots , x_n. There are three other cases: The coefficient A is bad, the module M is bad, and it is explainable from the choice of L and X. (badness is measured by how far the module is from a vector space)

  1. Consider \bar {2} \cdot \bar {3} = 0 in \mathbb {Z} / 6 \mathbb {Z} as a \mathbb {Z} / 6 \mathbb {Z} -module. The coefficient \bar {2} in \mathbb {Z} / 6 \mathbb {Z} is already a zero divisor, so we can blame the syzygy on the coefficient ring \mathbb {Z} / 6 \mathbb {Z}.
  2. Consider 2 \cdot \bar {3} = 0 in \mathbb {Z} / 6 \mathbb {Z} as a \mathbb {Z}-module. The coefficient 2 in \mathbb {Z} is good; it is not a zero divisor in \mathbb {Z}, but \bar {3} in \mathbb {Z} / 6 \mathbb {Z} has the property that adding it to itself is zero; it is a torsion element. So the cause of this syzygy should be counted on the module \mathbb {Z} / 6 \mathbb {Z}.
  3. Consider 2 \cdot (1/3) + (-3) \cdot (1/2) = 0 in \mathbb {Q} as a \mathbb {Z}-module. The choice of coefficients L = \begin {bmatrix} 2 & -3 \end {bmatrix} naturally has the potential to be canceled in \mathbb {Z}: take 3, 2 \in \mathbb {Z}, set G = {\begin {bmatrix} 3 & 2 \end {bmatrix}}^{\intercal }, then L G = \begin {bmatrix} 2 & -3 \end {bmatrix} {\begin {bmatrix} 3 & 2 \end {bmatrix}}^{\intercal } = 0. The elements X = {\begin {bmatrix} 1/3 & 1/2 \end {bmatrix}}^{\intercal } in the module happened to be multiples of G: X = {\begin {bmatrix} 1/3 & 1/2 \end {bmatrix}}^{\intercal } = {\begin {bmatrix} 3 & 2 \end {bmatrix}}^{\intercal } \begin {bmatrix} 1/6 \end {bmatrix} = G Y where Y = \begin {bmatrix} 1/6 \end {bmatrix}. So L X = L G Y = 0 Y = 0. We cannot blame this syzygy on the module \mathbb {Q}; these coefficients would naturally be eliminated LG = 0 within the ring A.

Formalizing this intuition, we say:

Definition Explainable syzygy and Flat module

  • November 13, 2026
  • Hsu Ching Chung

A syzygy LX = 0 in M is explainable if there exist G \in A_{n \times m}, Y \in M_{m \times 1} such that:

  • LG = 0 (the coefficient L naturally has the potential to be canceled in A) and
  • X = GY (the module elements X happen to lie in the image of G).

An A-module M is flat if every syzygy in M is explainable.

This definition of a flat module gives an intrinsic description of a flat module, rather than an extrinsic view; M \otimes _A - is an exact functor. The two ways have different advantages. I can’t say which one is the better definition, but I want to emphasize the naming: syzygy and explainable give a strong intuition. I think the name of a generalized element also has the same spirit! (Why a flat module is called flat is still a mystery) This book also has a small poem at the beginning of the chapter on flat modules:

Dear elements,

If you aren’t free,

it isn’t my fault.

A flat module.

I think it is cute!

      Fix an object A in a category \mathcal {C} with a terminal object 1.

      An assignment (a_\Gamma )_\Gamma of a generalized element a_\Gamma : \Gamma \rightarrow A of A for each object \Gamma in \mathcal {C} is called a global assignment of generalized elements of A if it is invariant under context substitution in the sense that: a_\Delta \sigma = a_\Gamma for all morphisms \sigma : \Gamma \rightarrow \Delta in \mathcal {C}.

      Show that there is a one-to-one correspondence between global elements c : 1 \rightarrow A of A and global assignments of generalized elements (a_\Gamma )_\Gamma of A.

      Proof.

      • October 30, 2026
      • Hsu Ching Chung

      Given a global element c : 1 \rightarrow A of A, we can consider the assignment of generalized elements of A: c {!}_\Gamma : \Gamma \rightarrow 1 \rightarrow A for each object \Gamma , where the morphism {!}_\Gamma : \Gamma \rightarrow 1 is the unique morphism into the terminal object 1. Then (c {!}_\Gamma )_\Gamma is invariant under context substitution since for any morphism \sigma : \Gamma \rightarrow \Delta , we have {!}_\Gamma = {!}_\Delta \sigma by the uniqueness of {!}_\Gamma , and so c {!}_\Gamma = c {!}_\Delta \sigma .

      Conversely, let (a_\Gamma )_\Gamma be a global assignment of generalized elements of A. We have a global element a_1 : 1 \rightarrow A of A.

      We check that these two constructions are inverses of each other:

      • c {!}_1 = c: Since {!}_1 = \operatorname {id}_1 : 1 \rightarrow 1 by the uniqueness of {!}_1, we have c {!}_1 = c \operatorname {id}_1 = c.
      • a_1 {!}_\Gamma = a_\Gamma : Since (a_\Gamma )_\Gamma is "invariant under context substitution", taking \sigma := {!}_\Gamma : \Gamma \rightarrow 1 gives a_1 {!}_\Gamma = a_\Gamma .

      Definition of subobjects [000F]

      • November 2, 2026

      For the generalization of a subset, we should look at a monomorphism i : U \hookrightarrow A. In the notation of generalized elements, the condition of i : U \hookrightarrow A being a monomorphism is exactly that, for all generalized elements x, y of U with the same context, if i x = i y then x = y. Notice that i x, i y are generalized elements of A. Therefore, for each object \Gamma , the post-composition by i: \begin {aligned} (i \circ ) : \operatorname {Hom}_\mathcal {C}(\Gamma , U) &\rightarrow \operatorname {Hom}_\mathcal {C}(\Gamma , A) \\ x &\mapsto i x \end {aligned} can be seen as an inclusion map from generalized elements of U to they of A.

      We can recover the notation of an element lying a subset, the inclusion relation between two subsets, and when two subsets are considered equal.

      Definition. Subobject membership relation [0007]

      • October 31, 2026
      • Hsu Ching Chung

      Let x : \Gamma \rightarrow A be a generalized element of an object A and u : U \hookrightarrow A be a monomorphism in a category \mathcal {C}. We say x is lying in u, denoted by x \in u, if x factors through u; that is, we have x = u \phi for some morphism \phi : \Gamma \rightarrow U.

      Notice that such a \phi is unique: if x = u \phi and x = u \psi for some \phi , \psi : \Gamma \rightarrow U, then u \phi = u \psi , which implies \phi = \psi since u is a monomorphism.

      Definition. Subobject inclusion relation [0008]

      • October 31, 2026
      • Hsu Ching Chung

      For monomorphisms u, v into the same object A in a category \mathcal {C}, we say u is included in v, denoted by u \le v, if x \in u \text { implies } x \in v for all generalized elements x of A. Recall that x \in u denotes the subobject membership relation.

      Definition. Subobject equivalence relation [0009]

      • October 31, 2026
      • Hsu Ching Chung

      Two monomorphisms u, v into the same object A in a category \mathcal {C} are considered equivalent if u \le v \text { and } v \le u, denoted by u \sim v. Recall that u \le v denotes the subobject inclusion relation.

      After we have the membership relation x \in u, all the other definitions u \le v, u \sim v mimic the behavior of a subset in set theory.

      Notably, in the above definition of inclusion u \le v, we hide the sources \Gamma , U, V of morphisms x, u, v intentionally because they are somehow irrelevant in actual proofs about the properties of: lets us write computations more like we are dealing with sets. In the following exercise, try to avoid explicitly writing the sources of morphisms as much as possible!

      We will see some examples of monomorphisms in the next section. First, let us make sure those definitions have the properties we expected and verify they match the definitions in nLab.

      Exercise. Properties of u \le v and u \sim v [000A]

      For any monomorphisms u,u',v,v',w into A in a category \mathcal {C} and generalized element x of A, show the following:

      1. u \le v if and only if u factor through v.
      2. u \sim v if and only if u = v \phi for some isomorphism \phi : U \cong V, where U, V are the source of u : U \hookrightarrow A, v : V \hookrightarrow A respectively.

        • u \le u.
        • If u \le v and v \le w then u \le w.

        • u \sim u.

      Definition. Subobject [000B]

      • November 2, 2026
      • Hsu Ching Chung

      The subobjects on an object A in a category \mathcal {C} are the equivalence classes of monomorphisms into A quotiented by the subobject equivalence relation \sim , denoted by \operatorname {Sub}(A). In notation: \operatorname {Sub}(A) := \set { u | u : U \hookrightarrow V }/{\sim }.

      As an abuse of notation, for two monomorphisms u,v into A, instead of writing [u] for the subobject represented by u and [u] = [v] for u, v are representing the same subobject, we just write u \in \operatorname {Sub}(A) and u \sim v.
